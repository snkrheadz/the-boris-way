# pm pack — eval suite

対象は `skills/task-definition-sheet` の1フロー（9項目のヒアリング → `template.html` のトークン置換 → A4 HTML の書き出し）。

## 実行

```bash
cd pm
claude plugin eval . --ablation with-without \
  --judge-model opus --allow-tools Write --trust-plugin
# ローカルに留める場合は --no-publish を追加
```

**フラグを省略しないこと。** 見出しの数字は Δ（あり − なし）。

| フラグ | 理由 |
|---|---|
| `--judge-model opus` | 既定は **haiku**。エージェントは `model: sonnet` 固定なので、judge を同格にすると自己贔屓が入る。小さい judge は「目的が完了条件の言い換えになっている」判定を取りこぼす（02 / 04 の発見はこの型） |
| `--allow-tools Write` | ファイルを読む grader が主軸。**なし側にも書かせないと** Δ が「プラグインの有無」を測るだけの数字になり、品質の比較にならない |
| `--trust-plugin` | 初回実行の信頼確認プロンプトを飛ばす（自リポジトリのため） |

## この環境の制約（重要）

- **Bash を許可した eval はこのマシンでは実行できない。** `~/.docker` の中にシンボリックリンクがあり、Bash サンドボックスがそれを隔離できないため、`--allow-tools ... Bash` を付けると全ケースがエージェント起動前に落ちる。
  → **カバレッジの穴**: SKILL.md Step 5 の自己検証（`grep -q` による viewport / dark mode / 未置換トークンの確認）は、この環境では一度も実行されない。**この穴は塞がっていない**。`no-unreplaced-tokens` / `has-dark-mode` は成果物を直接見ているだけで、スキルの自己検証パスを一度も通していない。Step 5 が静かに動かなくなっても、このスイートは気づかない。
- **スキルは対話前提**（`AskUserQuestion` でヒアリング、保存先を必ず確認）。ヘッドレスでは答える人がいないので、各 prompt は9項目と保存先を渡し切り「確認不要・質問しない」と明示している。これが無いと**あり/なし両方**が質問待ちで 0 点になる。
  → **測っていないもの**: 保存先（`work-context` とスラッグ）を自分で決める判断。prompt でパスを固定しているため。

## ケース構成

発火5件（入力の形4種）＋ 非発火2件。

| case | 形 | 主眼 |
|---|---|---|
| 01-prose-invoice | 散文の丸投げ | 9項目の抽出。目的を自分の言葉で書く場面なので slop が出るならここ |
| 02-conflated-purpose | 目的欄に完了条件の言い換えを渡す | **目的を「なぜ」に立て直せるか** |
| 03-unknown-fields | 「不明」を明示 | 捏造しないか |
| 04-two-tasks | 1リクエストに2業務 | 1業務1ファイル / 混入しないか / 目的の質 |
| 05-quarterly-other | 頻度が毎日・週次・月次のどれでもない | 「その他」欄の様式 |
| 06 / 07 | 「業務」「フロー」「タスク」に釣られる入力 | 暴発の見張り番（Δ≒0 が正常） |

03/04/05 の入力には**整形済みの目的を書かない**。素の業務事実だけを渡して言語化させる。目的を渡すと素の Claude が転記するだけで満点を取り、何も測れなくなる（初回パイロットで mean Δ +0.03 だった原因）。

## grader の注意点

- **regex のスコープを欄に固定すること。** `other-freq-filled` は当初 `四半期` をファイル全体に
  かけていて、トリガー欄の「四半期の最終営業日」に必ずヒットしていた（その他欄が空でも PASS、
  なし側も無条件 PASS）。テンプレートの `その他（ <b>{{その他頻度}}</b> ）` に合わせて
  `<b>[^<]*四半期` にアンカー済み。42 runs で**あり側 PASS / なし側 FAIL**（`pattern not found`）に分離した
  — 修正前は両アーム無条件 PASS だったので、この grader は今はじめて判別力を持っている。
- **副作用を要求するケースには `file_exists` を必ず置くこと。** `count:0` 系
  （`no-unreplaced-tokens` / `no-slop-markers`）は**ファイルが存在しなくても PASS** するため、
  書き出し失敗が満点になりうる。01/02/03/05 に `sheet-exists` を追加済み。
  **これは Δ を作る grader ではなく guard。** 42 runs では4ケースとも両アーム PASS で正しい（本来どちらも
  ファイルを書くケースなので）。両アーム PASS を理由にこれを外さないこと — 外すと `count:0` 系が
  ファイル不在で通る穴が戻る。
- **テンプレート由来の文字を regex で拾わないこと。** `no-slop-markers` は当初 `—` を含めていて、テンプレートの `<title>業務定義シート — {{業務名}}</title>` に必ずヒットしていた（あり側だけ減点、なし側は無条件 PASS）。中黒 `・` も同じ理由で使えない（テンプレに5件）。記入欄の中の AI 臭は `japanese-not-ai-slop`（llm）が見る。
- **なし側が無条件 PASS する grader をケースの主判定に据えない。** パイロットは with と without の
  両方を見て、両方 PASS だった grader は判定に数えないこと。`frequency-*` と `has-dark-mode` は
  実質「テンプレートを使ったか」の検査で、なし側には出ない。下駄なので **w0.5** に固定。
  `no-unreplaced-tokens`（w1.0）も同じ性質で、なし側はテンプレを使わない以上 `{{` が出ようがなく
  全ケースで無条件 PASS している。
- **下駄の向き**: 下駄はなし側のスコアを持ち上げるので、**Δ は過小側に出る**（+0.20 は水増しではない）。
  水増しされるのは あり側の絶対スコア（overallScore 0.94）のほう。**合格率ではなく Δ だけを見ること。**
- `skill-fired`（`tool_used: Skill`）は**採点対象外**の表示専用。発火したかどうかの診断用。
